# GachaNight

Rubber-hose pixel-art incremental game set in a retro Japanese toy store, seen
from a raised oblique camera. You wake up locked
in at night with three coins: spin capsule machines, sell or keep the figures,
complete collections, buy upgrades and robots at the reception computer, sleep on
the staff room sofa to be reborn with permanent upgrades, and finally buy the key,
open the front door and leave.

`GachaNight_MASTER_DESIGN.md` is the source of truth for the design (in Spanish).
Agent workflow rules live in `AGENTS.md` and `.codex/`.

## Requirements

- Godot 4.7 (standard build, GDScript). The project uses the Compatibility renderer.
- Only to regenerate assets: Python 3 with Pillow (`pip install pillow`).

## Run

Open the folder in the Godot editor (it imports the assets the first time) and
press F5. From a terminal:

```
godot --headless --path . --import   # once, after cloning
godot --path .
```

Controls: `WASD` or arrow keys walk on the floor in both axes, `Shift` run, `E` use what you stand next
to, `Tab` catalog, `Esc` close a panel or open the pause menu (volume, music,
fullscreen, Save & Quit). `Space` skips the ending text. The mouse is only used
in menus.

## Tests

```
godot --headless --path . -s tests/run_tests.gd     # game rules
godot --headless --path . -s tests/smoke_boot.gd    # boots the main scene and plays the whole loop
godot --headless --path . -s tests/sim_balance.gd   # simulated player, reports story length
```

All three exit non-zero on failure. Details:

- `run_tests.gd` runs the rules on frozen tables in `tests/data/`, so rebalancing
  the game does not change what it asserts. One test also loads the shipped
  tables and checks the values the design fixes.
- `smoke_boot.gd` drives the real interactions and buttons from the bathroom to
  the credits, on its own scratch save. Run it without `--headless` and with
  `GACHANIGHT_SHOT_DIR` set to a folder to also save screenshots.
- `sim_balance.gd` accepts `-- --seed=N --quiet`. It passes when the story takes
  120-180 simulated minutes with at least 3 rebirths.

## What is in the game

- The store is one strip of rooms with a deep floor: bathroom, corridor, hall,
  gallery, reception and staff room.
- Bathroom start with 3 floor coins, main power switch, lit store.
- Six machines: Capsule Machines No. 1-4, the Crane Catcher and Lucky Plinko, all
  ending in the same Sell or Keep decision. The crane always gives a prize.
- Thirty figures over five rarities, in six series. Collections are per figure;
  completing one gives pending prestige and a bonus for the rest of the run.
- Catalog available from the start: every figure is listed, undiscovered ones as
  the dark silhouette of their own sprite. Discovery is permanent. In the
  gallery every figure stands on the base of its rarity (plain puck to gold
  trophy); silhouettes never show a base.
- Machines are living rubber-hose characters: asleep without power, they wake,
  idle and crank themselves. Around them the store has some forty ambient loops.
- Reception computer (a very keen sales terminal): coin upgrades, robots that
  work the machines, and the Store Exit Key. Everything bought there is lost on
  rebirth.
- Sofa: unlocked by the first use of Machine No. 2. Permanent upgrades are chosen
  provisionally and only charged by `Sleep & Rebirth`; leftover points are banked.
- Ending: buying the key does nothing by itself; using it on the front door plays
  the ending and credits, then Free Play continues in the same store.
- Autosave of permanent and run state with a backup file; an unresolved prize
  comes back after a restart.
- Generated pixel-art sprites and animation sheets for figures, machines, props
  and characters; generated sound effects, a store hum and two tunes.

## Provisional content

The design document marks many things as examples or pending. In this build they
are filled with first-pass values, none of them approved design:

- All balance: machine prices from No. 3 on, sale values, weights, upgrade and
  robot costs, the prestige tree, the key price. Tuned only against the simulated
  player (five seeds finished in 123-177 minutes with 4-6 rebirths); no person
  has played it through.
- Figure names, series names, looks and collection bonuses.
- Store layout, sign and poster text, the salesman's lines, ending text and
  credits (`data/credits.json`).
- The top rarity is shown as "Legendary". The ending does not explain the mystery.
- Sprites and audio are generated by scripts: consistent with the art direction,
  but a first pass rather than final art.

Not built: Steam packaging and store builds, macOS verification, gamepad support,
key rebinding, machines 007-010, offline earnings, other languages. Before
exporting a build, add `*.json` to the export filter so the data tables ship.

## Changing things

- Balance lives in `data/*.json`. `machines.json` and `figures.json` are generated
  from one table by `python tools/make_data.py`; edit prices, sale factors, names
  and looks there and re-run it. Then check `tests/sim_balance.gd`.
- Art generators, each verifying its own output: `python tools/pixel/build_machines.py`
  (machines, their animations and `anchors.json`), `build_figures.py` (figures, idle
  loops, rarity bases), `build_anims.py` (protagonist, robot, effects),
  `build_environment.py` (tiles, props), `build_ambient.py` (ambient loops).
- Each asset folder with animations has its own `anims.json` manifest.
- They write contact sheets to `tools/pixel/previews/` (not shipped).
- `diseños/` holds the owner's style references.
- Audio: `python tools/make_audio.py`.
- After regenerating assets, run `godot --headless --path . --import`.

## Layout

```
data/               balance tables, credits
scripts/core/       definitions loader, permanent/run state, GameCore, number format
scripts/services/   economy, machines, collections, prestige, reception, automation, save
scripts/world/      store, player, interactables, sprite loader, main scene script
scripts/ui/         HUD, prize panel, catalog, sofa menu, reception terminal, ending
scripts/game.gd     "Game" autoload: owns the GameCore, ticks robots, autosaves
scripts/audio.gd    "Audio" autoload
assets/             generated sprites, animation sheets and audio
tools/              asset and data generators
tests/              rule tests, scene smoke test, balance simulation, fixture tables
```

Rules live in `scripts/core` and `scripts/services` and do not depend on scenes.
World and UI code call `GameCore` and listen to its signals; they do not change
coins, copies or prestige themselves.

The save file is `user://gachanight_save.json` (schema version 1).
